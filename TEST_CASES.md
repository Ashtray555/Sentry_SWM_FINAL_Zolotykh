**Detailed requirement-to-case links:** see `TRACEABILITY_MATRIX.md`.

## Conventions

- Evidence paths are to be recorded under `logs/`, with firmware version in each filename.
- Record exact command, expected result, actual result, outcome, and any bug ID.
- Where physical behavior is specified, UART output alone is not sufficient evidence.
- On 2.1.0, Guard/Alert/K4 cases marked N/A should confirm the documented planned-feature behavior only when useful; do not file the planned response as a bug.
- Boundary notation: for a valid interval `[min,max]`, test `min-1`, `min`, `min+1`, `max-1`, `max`, and `max+1` where numeric input permits.
